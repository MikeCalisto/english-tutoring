# ТЗ: english tutoring platform — сборник по временам английского языка

Документ для Claude Code. Вместе с ним передаются:

- `rules.md` — свод из 18 правил дизайна и подачи, накопленный при согласовании макета. **Обязателен к соблюдению, спорные места решены там.**
- `build/` — работающий генератор карточек и данные по девяти темам.
- `cards.html` — собранный результат, 31 карточка. Смотреть здесь, как всё должно выглядеть.
- `prototype.html` — ранний макет, оставлен как справка по вёрстке блоков, которых пока нет в генераторе.
- папка со скриншотами фреймов доски Miro — источник содержания.

Порядок чтения: сначала `rules.md`, потом открыть `cards.html` в браузере, потом разобрать `build/data/present-simple.json` как образец схемы.

---

## 1. Что за продукт

Мини-продукт, который делают двое: заказчик и эксперт-преподаватель английского.

**Аудитория:** учителя английского, репетиторы, преподаватели.

**Проблема аудитории:** плохо получается объяснять ученикам времена. Ученики плохо воспринимают времена на словах.

**Решение:** визуальный сборник материалов. Не курс и не уроки — именно сборник, к которому учитель обращается **во время занятия**: открыл нужную карточку, показал ученику, объяснил.

Отсюда следуют два требования ко всему продукту:

- Карточка должна читаться за несколько секунд и с расстояния — её показывают с экрана или проектора.
- Ничего нельзя объяснять словами там, где можно показать. Поэтому таймлайны вынесены в отдельную вкладку и занимают в продукте столько же места, сколько сами карточки.

**Два формата поставки:**

1. Веб-платформа — всё в одном месте.
2. Отдельный PDF.

---

## 2. Состав: четыре вкладки

Одна вкладка = один блок продукта.

| вкладка | содержание |
|---|---|
| 1. Карточки времён | Карточки по каждому времени: форма, правописание, употребление |
| 2. Таймлайны | Визуализация каждого времени на временной шкале + конфликты времён |
| 3. Интерактивные задания | Ссылки на Wordwall, разбитые по временам, около 20 штук |
| 4. Тесты | Перенесённые тесты с автоматической проверкой |

---

## 3. Объём контента

На доске Miro 18 фреймов:

**12 времён:** Present Simple, Present Continuous, Present Perfect, Present Perfect Continuous, Past Simple, Past Continuous, Past Perfect, Past Perfect Continuous, Future Simple, Future Continuous, Future Perfect, Future Perfect Continuous.

**3 смежные темы:** To be going to, Stative verbs, Used to.

**2 служебных фрейма:** Irregular verbs, Сочетание времен (это и есть конфликты времён для вкладки 2).

Итого около 50 карточек и около 20 таймлайнов.

## 4. Что уже сделано и передаётся готовым

**Генератор карточек работает.** Карточки не верстаются руками — они собираются из JSON.

```
build/
  build.py      генератор: JSON -> HTML
  style.css     утверждённый CSS, извлечён из prototype.html
  data/
    _order.json         порядок тем в итоговом файле
    present-simple.json
    present-perfect.json
    present-perfect-continuous.json
    past-continuous.json
    past-perfect.json
    past-perfect-continuous.json
    combinations-pairs.json
    combinations-scenarios.json
    combinations-overviews.json
cards.html      результат сборки, 31 карточка
prototype.html  ранний макет, оставлен как справка по вёрстке
```

Сборка: `cd build && python3 build.py`. Результат кладётся в `cards.html`.

**Менять вёрстку — только в `build.py` и `style.css`. Менять содержание — только в `data/`.**

### Готовые типы карточек

| тип | поле `type` | что рисует |
|---|---|---|
| форма | `form` | панели POSITIVE / NEGATIVE / QUESTION / SHORT ANSWER / CAREFUL |
| содержание | нет | блоки: правописание, употребление, чипы, таблицы, сценарии |
| сравнение | `compare` | два-четыре времени в колонках со своими случаями и выражениями времени |

### Виды блоков внутри карточки содержания

`spelling`, `pairs`, `chips`, `uses`, `text`, `lines`, `careful`, `scenario`, `table`.

Схемы полей смотреть по готовым файлам в `data/` — они и есть документация.

## 4b. Таймлайны

Таймлайнов пока нет ни для одного времени, кроме трёх образцов в `prototype.html`. Нужен компонент по той же схеме: один рендерер, данные в JSON.

```json
{
  "id": "present_continuous",
  "title": "Present Continuous",
  "subtitle": "an action in progress",
  "group": "present",
  "nowAt": 0.5,
  "nowLabel": "NOW",
  "spans":  [ { "from": 0.30, "to": 0.66, "label": "action in progress" } ],
  "points": [],
  "ticks":  [ { "at": 0.30, "text": "9:00" }, { "at": 0.5, "text": "11:20" } ],
  "timeMark": { "from": 0.5, "to": 0.5, "text": "at the moment" },
  "sentence": [
    { "text": "Chris " },
    { "text": "is painting", "mark": "verb-span" },
    { "text": " the garage " },
    { "text": "at the moment", "mark": "time" },
    { "text": "." }
  ],
  "note": "The action is still going on. NOW sits inside the block, so the action is unfinished."
}
```

Координаты — доли от 0 до 1. Тот же компонент рисует и конфликт двух времён: два набора `spans` и `points` с разными цветами.

## 5. Вкладка 1: карточки

Типы карточек на одно время:

1. **Form** — смысловые глаголы
2. **to be** — если у времени есть отдельная форма глагола be
3. **Spelling** — правописание окончаний, плюс смежные темы вроде наречий частотности или неправильных глаголов
4. **is used** — все случаи употребления и выражения времени, на одной карточке

Не все времена имеют все четыре типа. У Present Continuous нет отдельной карточки be — она внутри формы.

Всё остальное по вёрстке и подаче — в `rules.md`, правила с 1 по 16. Особенно важные:

- Содержимое карточек на английском. Украинский только в интерфейсе платформы.
- Местоимения отдельными пилюлями в столбик, скобка охватывает столбик.
- Панели по две в ряд, выровнены по высоте, пустых половин нет.
- Текст нейтральный, ключевые слова жирным и в цвет роли.
- Цвет роли одинаков на всех карточках, цвет рамки = группа времени.

## 6. Вкладка 2: таймлайны

Отдельный раздел. В карточках времён таймлайнов нет.

- Всё содержимое на английском, включая объяснения и легенду.
- Глагол-показатель времени и выражение времени подсвечиваются **разными** цветами.
- Время на шкале условное, иллюстративное.
### Карточки конфликтов времён

Это ядро всей вкладки, ради него продукт и задумывался. Учителя жалуются, что ученики не улавливают разницу между похожими временами. Карточка конфликта показывает **два времени на одной шкале**, чтобы разница была видна глазом, а не объяснялась словами.

Как это работает на примере, который дал заказчик. Предложение с союзом `when`: одно действие длилось, второе его прервало. На шкале длительное действие рисуется полосой, прерывающее — крестиком внутри этой полосы. Ученик видит, что одно время отвечает за отрезок, а другое за точку, и почему в этом предложении они стоят именно так.

Требования к карточке конфликта:

- Оба времени на одной шкале, каждое своим цветом.
- В предложении под шкалой глаголы обоих времён подсвечены теми же цветами, что и их метки на шкале.
- Выражение времени подсвечивается третьим цветом, отдельно от глаголов.
- Под шкалой — короткое объяснение по-английски, что произошло раньше и что кого прервало.

Источник содержания — фрейм `Сочетание времен`, а также готовые карточки сравнения в `build/data/combinations-*.json`: там уже разобраны Present Simple vs Past Simple, Present Perfect vs Past Simple, Past Continuous vs Past Simple, Past Perfect vs Past Perfect Continuous, Will vs Be going to, и сценарии, где одна и та же ситуация показана в трёх временах.

## 8. Вкладка 4: тесты

Заказчик даст ссылку на сайт с готовыми тестами. Их нужно перенести на платформу и сделать **автоматическую проверку**.

Результаты сохранять в базу с привязкой к ученику. Не показывать на экране и забывать — они понадобятся для проверки работ учителем в следующей версии.

## 9. Доступ и авторизация

**Продажа и выдача:** бот на Zenedu. Бот выдаёт доступ к платформе и PDF-файлы.

**Вход:** авторизация через Telegram, привязка по аккаунту.

**Задача:** учителя не должны бесплатно передавать доступ друг другу.

**Отдельная проблема:** учитель должен уметь дать ученику доступ к тестам, не открывая при этом дыру.

Предложенная модель, требует утверждения заказчиком:

- Роль «ученик» с урезанными правами: видит только таймлайны и тесты. Ни карточек, ни Wordwall, ни PDF, ни скачивания.
- Приглашения генерирует сам учитель в личном кабинете. Персональная ссылка или код, привязанный к его аккаунту, с лимитом на количество учеников.
- Ученик входит по одноразовому коду, без Telegram.
- Против передачи логина между учителями: одна активная сессия на аккаунт плюс лог входов.

**Важно для будущего:** связка «учитель — ученик» должна быть заложена в схему данных с самого начала как полноценное отношение, а не как разовое приглашение. На ней потом строится вся вторая версия.

## 11. Перспектива развития — не в MVP

Платформа может вырасти из сборника материалов в рабочий инструмент учителя:

**Проверка работ.** Учитель видит работы своих учеников, включая тесты, и проверяет их.

**Учёт занятий.** Вкладка, где учитель отмечает проведённые занятия.

**Финансовый учёт.** Та же вкладка, мобильная вёрстка, отдельного приложения не делаем. По каждому ученику:

- сколько заплатил
- на сколько занятий хватит оплаченного
- когда следующая оплата
- сколько заплачено наперёд, сколько должен
- сколько учитель заработал всего

«На сколько хватит» и «когда следующая оплата» считаются автоматически. Для этого в схеме данных нужны: стоимость занятия у конкретного ученика, поступившие платежи, проведённые занятия. Баланс = оплачено минус проведено, остаток делим на цену.

Учёт занятий и финансы — не два раздела, а один: отметил занятие проведённым, баланс ученика уменьшился.

## 12. Что решить до старта

- **Название.** Ещё не выбрано, продукт пока описывается как english tutoring platform. В подвале карточек заглушка. В код название не заводить, держать в одном конфиге (правило 18).

- **Стек.** На чём пишем, где хостим, где храним пользователей и результаты тестов.
- **Формат карточки.** Фиксированный лист (например A4 landscape) или высота по содержимому. От этого зависит вся вёрстка.
- **Иконки.** Сейчас эмодзи. Альтернатива — свой набор иконок в единой линии, дороже, но выглядит дороже.
- **Подвал карточки.** Сейчас заглушка `ЧАСИ АНГЛІЙСЬКОЇ`. Нужны название продукта и логотип.
- **Схема оплат.** Пакеты занятий, помесячно, разово — или хватит одной схемы.
- **Точное число заданий Wordwall.** Сейчас «около двадцати».

---

## 13. Чего делать не нужно

- **Не придумывать содержание.** Грамматика, примеры предложений, названия случаев употребления берутся дословно со скриншотов. Если на исходнике есть две панели с разными примерами на один случай — берётся объединение, ничего не выбрасывается.
- **Не переизобретать вёрстку.** `prototype.html` утверждён. Отклонения от него — только через новое согласование.
- **Не отклоняться от `rules.md`.** Там уже решены вопросы, которые кажутся открытыми.
- **Не считать содержание проверенным.** Карточки собирает Claude Code, но грамматику и качество примеров вычитывает эксперт-преподаватель. Это ручной шаг, его надо закладывать в план.

---

## 14. Отдельная задача перед продажей

Примеры предложений сейчас взяты с исходных постеров дословно. Постеры принадлежат сторонним сайтам и учебникам. Перед запуском продаж примеры нужно пройти одним проходом и заменить на собственные — грамматические правила при этом не меняются, только конкретные предложения.

Задача небольшая, но её нельзя забыть: продукт платный и продаётся той же аудитории, которая эти постеры знает.
